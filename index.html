規則三規範

週期性會議 (Recurring Meetings) 衝突原子性驗證

支援每週 (WEEKLY) 重複會議。若選擇 ALL_OR_NOTHING，只要任何一週發生衝突即刻整批回滾（Rollback），不留孤兒預約。

💡 提示：在第 3 週故意安排一場突發 VIP 會議，可觀察 ALL_OR_NOTHING 如何整批回滾與提示衝突。

點擊送出查看週期展開結果、各週排程狀態與衝突報告

規則四規範

臨時維護需求與管理員覆蓋 (Temporary Maintenance Override)

臨時維修具最高優先權。若時段內已有預約，管理員可開啟 override_affected = True 強制驅離既有會議並轉為 `CANCELLED_BY_MAINTENANCE`。

若未勾選且該時段有已確認預約，系統將拒絕排定維護以保護使用者會議。

點擊排定維護觀察鎖定效果或驅離受影響預約過程

核心設計目標 (Core System Architecture)

本系統採用 Python 3.10+ 原生標準庫實現，無額外外部相依，遵循乾淨架構（Clean Architecture）與領域驅動設計（DDD），將領域模型（Models）、衝突檢驗器（ConflictChecker）、週期生成器（RecurrenceService）與應用服務（ReservationService）徹底解耦。

五大商業條件數理模型與檢測公式

規則一：時段重疊判定

左閉右開區間 $[S, E)$ 交叉檢定：

candidate.start < other.end and other.start < candidate.end

規則二：緩衝時間衝突判定

雙向延伸緩衝時間 $B$ 檢定：

candidate.start < (other.end + B) and other.start < (candidate.end + B)

規則三：週期性會議原子原則

ALL_OR_NOTHING 全系列衝突即回滾：

if conflicts and policy == ALL_OR_NOTHING: raise RecurrenceConflictError

規則四：臨時維修與覆蓋模式

強制驅離既有會議並註記工號與原因：

res.status = CANCELLED_BY_MAINTENANCE; res.cancelled_by = admin_id

領域例外階層架構 (Exception Hierarchy)

ReservationSystemError (Base Exception)
├── RoomNotFoundError (找不到指定會議室)
├── ReservationNotFoundError (找不到預約記錄)
├── TimeSlotInvalidError (時間區間邏輯錯誤，例如 Start ≥ End)
├── TimeOverlapError (時段重疊衝突，拋出 conflicting_id)
├── BufferTimeViolationError (違反強制換場緩衝，拋出 required_buffer)
├── MaintenanceConflictError (維護時段衝突，拋出 maintenance_id 與 affected_ids)
├── RecurrenceConflictError (週期系列衝突，拋出 failed_instances 清單)
└── InvalidStateTransitionError (非法狀態轉移，例如重複取消)
